申请内测

申请按顺序处理，小批量放号。目前还没有自助注册流程——比起发给你一个坏掉的链接，我们更愿意直说。

在 GitHub 上提交申请
  • 你用的是哪个 Coding Agent（Codex / Claude Code / Cursor / 自研）
  • 项目大致类型，以及你最想守住的那条行为
  • 只在本地跑，还是也要接进 CI
打开申请表单 我们存什么

表单会以公开 issue 的形式打开，方便你自己回头查记录。请不要在里面贴源码、密钥或客户数据。

内测版包含什么

  • 一个项目、一个 Coding Agent，由改动后的 Hook 触发
  • 本地 Playwright 执行，每条结论都附证据
  • 由你审阅并保留的已批准预期——AI 只能提议，不能批准
  • 手动全量回归，外加一个用于定时回归的 CI 任务
  • 自带模型 Key：运行在你机器上，账单在你账号上

我们绝不索取什么

  • 你的源码或仓库 Token
  • 你的模型 API Key——这一页不会要，邮件里也不会要
  • 生产环境凭据、客户数据，以及任何你不愿意公开的内容

为什么走 GitHub

静态站没法诚实地承诺「安全地替你保存邮箱」，而一个会静默失败的收集表单比没有表单更糟。公开 issue 不需要后端，留得下可回溯的记录，追问也能在同一个地方继续。如果你的组织用不了 GitHub，在任何一条 issue 下回复，我们换别的渠道。
