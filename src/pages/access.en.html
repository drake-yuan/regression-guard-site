Request early access

Requests are handled in order, in small batches. There is no automated signup flow yet — and we would rather say that than email you a broken link.

Send the request on GitHub
  • Which coding agent you use (Codex, Claude Code, Cursor, or your own)
  • What kind of project it is, and which behavior you most want protected
  • Whether you would run it locally only, or in CI as well
Open the request form What we store

The form opens as a public GitHub issue, so the thread stays searchable for you. Please do not paste source code, credentials or customer data into it.

What the early access build includes

  • One project, one coding agent, triggered by a hook after each change
  • Local Playwright execution with evidence attached to every verdict
  • Approved expectations you review and keep — the AI can propose, never approve
  • Manual full runs, plus a CI job for scheduled regression
  • Bring your own model key: the run stays on your machine, the bill stays on your account

What we never ask for

  • Your source code or a repo token
  • Your model API key, on this site or by email
  • Production credentials, customer records or anything you would not post publicly

Why the request goes through GitHub

A static site cannot honestly promise to store your email securely, and a form that silently fails is worse than no form. A public issue needs no backend, keeps a record you can point to, and lets us ask follow-up questions in the same place. If your organisation cannot use GitHub, reply on any issue thread and we will find another channel.
